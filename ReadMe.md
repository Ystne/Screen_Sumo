# SUMO Episode Replay and Screenshot Tool

Two-step pipeline to replay traffic episodes (generated by RouteRL) and generate matplotlib screenshots of the network without opening the SUMO GUI. (Optional)

## Prerequisites

Ensure you have Python installed along with the following libraries:

- pandas
- traci (provided with SUMO)
- sumolib (provided with SUMO)
- matplotlib

Make sure SUMO is installed and its tools are accessible in your environment variables.

## Folder Structure

For the scripts to work correctly and remain portable (using relative paths), your project directory should look like this:

```text
your_project_folder/
├── replay.py                 # Script 1: Generates SUMO config
├── screen.py                 # Script 2: Runs simulation and captures screenshots
├── README.md
├── .gitignore
│
├── results/                  # REQUIRED: Your RouteRL experiment results (default: tbrf_ing_self_40avs_44_41)
│   ├── paths.csv             # All available routes
│   └── episodes/             # Episode logs
│       ├── ep0.csv
│       └── ep2400.csv
│
├── replays/                  # Generated by replay.py (contains .sumocfg and .rou.xml)
└── screenshots/              # Generated by screen.py (contains .png files)
```

**Note on the Network files:** The network files (e.g., `ingolstadt_custom2.net.xml`) are **not** in this repository. You must point the `replay.py` script to the external folder where your networks are stored using relative paths (e.g., `../URB/networks/...`).

---

## Step 1: Generate the Replay Configuration

The `replay.py` script reads an episode's CSV log and the `paths.csv` file. It extracts the vehicles, sorts them chronologically by their start time, assigns their chosen routes, and generates a clean SUMO `.rou.xml` file along with a `.sumocfg` configuration file.

**Command:**

```bash
python replay.py --episode 2400 --records results --network-dir ../URB/networks/ingolstadt_custom2 --network-name ingolstadt_custom2
```

**Arguments:**

- `--episode`: The episode number to replay (e.g., `2400`).
- `--records`: The folder containing `paths.csv` and the `episodes/` subfolder (default: `results`).
- `--network-dir`: Relative path to the folder containing the `.net.xml` file.
- `--network-name`: The name of the network file, without the `.net.xml` extension.
- `--out`: (Optional) The output folder for the generated files (default: `replays`).

**Output:** Creates `replays/replay_ep2400.sumocfg` and `replays/replay_ep2400.rou.xml`. The `.sumocfg` uses relative paths internally, making it completely portable.

---

## Step 2: Capture Screenshots

The `screen.py` script reads the generated `.sumocfg`. It launches SUMO in headless mode (no GUI), extracts the vehicle positions at specific times, and generates images using matplotlib.

**Command to capture every X seconds:**

```bash
python screen.py --config replays/replay_ep2400.sumocfg --interval 1000
```

**Command to capture at exact specific times:**

```bash
python screen.py --config replays/replay_ep2400.sumocfg --times 500 1000 2400
```

**Command combining both (interval + exact times):**

```bash
python screen.py --config replays/replay_ep2400.sumocfg --interval 1000 --times 2400
```

**Arguments:**

- `--config`: Path to the `.sumocfg` file generated in Step 1.
- `--interval`: (Optional) Take a screenshot every X simulated seconds.
- `--times`: (Optional) Take a screenshot at exact specific simulated seconds (can take multiple values).
- `--out`: (Optional) Output folder for the images (default: `screenshots`).

**Output:** Generates `.png` files in the `screenshots/` folder, named like `snapshot_t1000.png`.

## Troubleshooting

- **Error: "The route file '...' is not accessible"**: This means SUMO is failing to resolve the path. Ensure you are using the provided `screen.py` which automatically resolves relative paths from the `.sumocfg` file location.
- **Empty Screenshots**: Ensure your SUMO simulation actually has vehicles at the requested times. You can verify this in the terminal output which prints the number of vehicles at each capture.
